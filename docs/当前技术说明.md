# 指间月光 · 第一版

三个模式共用八指输入、钢琴采样与本地摄像头识别。完整内置德彪西《月光》原谱 MIDI（322.5 秒、1,468 个音符），保留原调和实际音高。

## 使用

打开发布网址，点击「开始 / 开启声音」，再点击「开启摄像头」。掌心朝向摄像头，先张开手指，再让指尖与同手拇指接触、松开。

| 模式 | 输入与行为 |
| --- | --- |
| 自由演奏 | 从左到右：左手小指、无名指、中指、食指 → Do Re Mi Fa（C4 D4 E4 F4）；右手食指、中指、无名指、小指 → Sol La Si Do（G4 A4 B4 C5）。中央 C = 261.63 Hz。 |
| 音乐引导 | 跟随提示唱名，在待敲音处触碰对应手指。按原曲调性映射唱名；原曲的升降号与八度自动发声。两个哆都能完成当前的哆。其余声部随进度自动演奏。 |
| 梦想模式 | 每次任意指尖接触拇指，立即奏响下一枚旋律音并推进画面。没有到线限制、提前输入队列或旋律定时播放。节奏由每次实际触碰决定。 |

屏幕琴键与 A S D F / J K L ; 键盘具有相同功能，空格暂停/继续。右侧「识别设置」可调整触碰灵敏度；如左右手标签不符，可手动交换。持续碰住不会连发，失去追踪后必须重新张开手指。

引导与梦想共用乐曲进度，切换模式会暂停，重新点击继续；「↺」从头开始。进度条可跳到指定旋律音。隐藏浏览器页面会暂停音乐。梦想模式默认只演奏旋律；播放栏的「伴奏」开关可选择加入其余声部，关闭时清除尚未播放的伴奏并淡出已发声的伴奏。开启时按相邻触碰估计伴奏速度，加速时取消未发生的旧伴奏，不集中补播。按原谱节奏且开启伴奏时保留全部 1,468 个音符。

梦想模式每次新的接触只推进一个旋律事件，重复音高仍逐个等待输入。双手/多指同帧合击合并为一次推进；不同指尖相隔不到 35 ms 的触碰归入同一合击。明确松开后的同指重击不受该合击窗口限制。自由模式保留八指独立发声与和弦。键盘长按自动重复不作为新按下，鼠标每次按下只处理一次。

## 本机运行

已安装 Node.js 时，在此目录运行 `node serve.mjs`，然后打开 `http://127.0.0.1:4192`。也可双击 `启动网页.cmd`。运行网页不需要安装 npm 依赖，`dist` 包含模型、运行库、音色及 MIDI。

摄像头需要 HTTPS 或本机 localhost / 127.0.0.1，不能直接双击 HTML。手机访问时使用已发布的 HTTPS 网址。

## 导入音乐与扩展

曲库新增《莫斯科郊外的晚上》EOP 1024 钢琴版（`moscow-nights-eop-1024-piano` / `r0001`），31.25 秒、199 个音符、58 个旋律事件、141 个伴奏音。直接读取独立音乐档案的 `performance.json`，保留原调 A 小调、原始时值及人工划定的旋律，不重新从 MIDI 提取。档案状态为 `needs-review`，琶音时序和反复展开待试听核对；并非已经完成审听的完整版录音转写。当前内置《月光》保持原先的播放版本。

网站运行曲库位于 `dist/assets/music-library/catalog.json`。新增或更新已归档歌曲时，在本项目执行 `node scripts/sync-song.mjs <独立 music-library 目录> <song-id>`，工具按归档目录的当前修订读取并核对校验和、音符分组，只复制网站播放所需的 JSON 与版本元数据，不改写独立档案，也不上传原始谱图或用户素材。更新后的曲目自动出现在「曲库」。运行测试并重新发布后，线上用户才能看到更新。

界面已支持标准 `.mid` / `.midi` 导入（5 MB、60,000 音符、一小时以内），可选择旋律音轨。文件仅留在当前浏览器内存，刷新后恢复内置《月光》。不做 MP3/WAV 自动转谱。

`dist/lib/music.js` 将 MIDI 转为 `notes`（全部音符）、`cues`（需要完成的旋律音）、`accompaniment`（其余音符）。默认提取所选音轨每个起音时刻的最高音，在旋律长音持续时过滤较低的琶音。内置《月光》包含开头跨谱表的音符，共 306 个手势提示。这是高声部提取策略，并非人工标注的声部分析；复杂的导入乐曲可通过更换音轨改善结果。

原曲音高不转调。引导唱名按 MIDI 当前调号映射到八个入口，变化音取最近唱名，实际声音始终取原 MIDI 音高；页面同时显示实际音名。MIDI 中没有调号时以 C 调映射，仅改变手指入口，不改声音。第一版未实现踏板控制器、弯音或多乐器音色，均使用钢琴采样。

`dist/lib/hand-worker.js` 在 Web Worker 内执行 MediaPipe 推理，GPU 不可用时回退 CPU。主线程只传递 ImageBitmap、处理触碰结果、播放声音与绘图；同一时刻只有一帧推理，不堆积旧画面。请求最高 60 fps 的摄像头视频，使用视频帧回调驱动采样，实际采样率仍受摄像头与推理速度限制。启动有明确阶段、取消和超时处理。

`dist/lib/gestures.js` 使用 MediaPipe 世界/图像关键点，并校正图像宽高比。灵敏度范围恢复为 0.22–0.46，默认 0.34；小指保留 1.25 倍容差，无名指为 1.04 倍。上一版的 0.14–0.24 范围加上两套三维距离取最大值，在实际使用中导致大量漏触碰，已撤回。

接触距离以图像平面距离为主、世界平面距离为辅（80% / 20%），两套深度估计共同支持的间隔作为较低权重的补充。只有共同支持较大深度分离时才否决接触；世界数据缺失时使用带较大容差的图像深度。单个深度离群值不会直接否决可见接近，也不会单独造成松开/重新触发。此策略优先恢复响应，并不能精确测量真实皮肤接触；遇到深度估计分歧时可能比上一版更容易触发。

八指独立记录触碰后的最小距离、分离后的最大距离。重新准备以本次触碰的距离为起点，不再要求退出整个触碰半径，也不再要求两帧明确张手。默认分离幅度为掌尺度的 0.14，最高灵敏度降低到约 0.07，再次接近要完成明确的回程。持续贴住或小幅静态抖动不连发；深度偏差也不会独自重置触碰。失去追踪后重新接近前，须观察到一次张开或分离。梦想模式继续将同时/近同时合击归为一次推进。

双手身份结合掌心位置、运动预测与标签置信度作全局匹配，短暂漏检保留轨迹。单帧分类翻转不会直接换手；持续至少六帧且 90 ms 的高置信度张手证据可纠正最初的错误标签。身份修正时清除接触状态，避免凭空发音。低置信度或重复标签仍保留两只手，左右手使用相同的接触逻辑。镜像只用于显示，不额外反转模型的解剖左右标签；手动交换开关仍可用。

`dist/lib/audio.js` 保留 Salamander 钢琴采样。自由模式恢复采样主体与适度尾音：自动持续约 1.05 秒后用 280 ms 淡出；摄像头快速松手时至少保留 360 ms 主体，再淡出 280 ms。同音重击会短淡出仍在释放的旧声部，避免尾音堆积；和弦独立发声。引导/梦想的包络仍按乐谱控制，暂停用 25 ms 收声，最多 48 个有效声部。

`Transport` 在引导模式按曲谱时间等待；梦想模式的旋律由 `dreamHit` 直接触发。`visuals.js` 中梦想音符按触碰次数布局，130 ms 下落反馈由输入驱动。背景星点缓慢移动，并支持系统减少动态效果偏好。主界面保留必要提示，来源信息收在说明弹窗。

后续工作重点：按真实使用反馈继续调整邻指误判、遮挡、左右手交叉以及模型漏检。合成输入测试不能替代真实双手标定；如果摄像头未采到一次分离/接近，程序无法恢复未被观察到的触碰。

## 验证

曲库集成验证：启动本机网页后运行 `node tests/library-browser.mjs`（可用 `TEST_URL` 指定测试地址）。覆盖新曲三个模式、58 次独立梦想输入、伴奏切换、切回《月光》、迟到请求不覆盖新选择、加载失败后重试与手机布局。新增逻辑测试校验归档文件 SHA-256、A 小调提示、音符分组及整曲演奏。

开发验证：`npm install` 后运行 `npm test`。49 项逻辑测试覆盖原曲音符与时序、两种曲谱模式、共同深度分离拒绝、单套深度偏差容忍、图像深度回退、手掌尺度与角度、接触抖动、首次触碰、默认/最高灵敏度下小幅分离后的 50 ms 连击、八指和弦、小指容差、双手轨迹与标签纠正、重复同音符逐次推进，以及伴奏开关。

启动 `node serve.mjs` 后运行 `node tests/browser.mjs` 与 `node tests/interaction-browser.mjs`（脚本含 Windows Chrome 默认路径）：真实模型初始化及合成视频推理、三种模式、12 个连续相同音高的鼠标逐次输入、Enter 长按防连发、伴奏开关、MIDI 导入、移动布局；模拟双手关键点通过完整 Worker/页面链路，验证 40 次双手成对发音、另 40 次带深度偏差的成对发音、引导模式双手输入、八指和弦、适度尾音，以及 20 次成对接触形成 10 次梦想合击。OfflineAudioContext 使用真实采样验证重复敲击、和弦峰值和自然收尾。

以上不代替真实双手和摄像头的现场标定。摄像头未采到的分离动作无法由软件恢复；实际速度与深度误差受设备、遮挡和视角影响。

## 输入设计参考

- [osu!mania DrawableNote](https://github.com/ppy/osu/blob/master/osu.Game.Rulesets.Mania/Objects/Drawables/DrawableNote.cs)：按下事件进入单个音符的判断入口。
- [StepMania ScreenGameplay](https://github.com/stepmania/stepmania/blob/5_1-new/src/ScreenGameplay.cpp)：向演奏逻辑区分首次按下与释放，不把键盘自动重复当作新输入。
- [MediaPipe Hand Landmarker](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker)：图像/世界三维关键点和主体左右手标签。网页借鉴输入边缘处理；梦想模式的旋律进度由玩家触碰推进，没有音游的固定音乐时钟或到线窗口。
