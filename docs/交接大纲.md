# 指间月光 · GitHub 协作交接

本仓库与 GitHub Pages 是唯一正式环境。音乐档案和交接资料必须提交到仓库，不能仅保存在某台电脑。旧 ChatGPT Sites 配置不可再用。

## 代码入口

- `dist/app.js`：模式、曲库、摄像头和页面事件。
- `dist/lib/music.js`：MIDI 提取与 Transport。引导模式等待正确指法；梦想模式由输入直接推进旋律。
- `dist/lib/library.js`：读取已划分旋律的档案，校验全部音符分配，不再次提取。
- `dist/lib/gestures.js`：八指接触、左右手关联、梦想合击归并。此次迁移没有重新调参。
- `dist/lib/audio.js`：钢琴采样与尾音；`hand-worker.js`、`hand-client.js` 为识别模型链路。
- `dist/lib/visuals.js`、`style.css`、`cosmos.css`：深空背景与键盘。保持简洁，来源说明收在弹窗。
- `dist/lib/pipa.js`、`pipa.css`：琵琶的三个模式及独立曲库；共享 `music.js` 的 Transport，不修改钢琴音色和触碰阈值。
- `dist/lib/pipa-gestures.js`：左拇指到四指尖的四弦、右食指跨线、往返与扫弦归组。用同一画面坐标和左掌局部坐标消除整体位移；不能直接比较以各自手掌为原点的 MediaPipe worldLandmarks。
- `dist/lib/pipa-audio.js`：自行编写的拨弦合成音色；不是实录琵琶采样。后续可替换音源，保持钢琴 `Piano` 的行为。

琵琶当前曲目为《茉莉花》试奏编配，权威档案在 `music-library/pipa/`，独立索引、修订与入库命令见该目录 README.txt。钢琴曲库仍在原路径；两库的选曲、进度和音频互不覆盖。页面默认钢琴，左上角切换。

琵琶音乐引导将原八级提示成对对应四弦：Do/Re→四弦、Mi/Fa→三弦、Sol/La→二弦、Si/高Do→一弦，实际音高保持原谱。这是试奏映射，不是实物琵琶按品法。梦想模式按独立拨动推进，每个拨弦点的同方向连续扫弦只推进一个事件；自由模式扫弦依次奏出全部经过的弦。单手演奏检测右食指、右中指；双手演奏检测左右食指，须先固定琴弦。两点独立计数，未实现按品。

运行 `npm run test:pipa` 检查三个模式、独立曲库、77 次梦想输入、模拟摄像头连拨与扫弦、切回钢琴及手机布局。该自动测试不等于真人识别或音色听感验证。

## 音乐流程

1. 读 `music-library/固定工作提示词.txt`、`README.txt`、`schemas/score.schema.json`。
2. 保留原调、实际音高、八度、时值；相同音高重新起音必须有独立事件。记录输入来源与不确定性。
3. 用 `node music-library/tools/archive.mjs add ...` 生成新修订，不覆盖旧修订。
4. 运行 `node music-library/tools/archive.mjs validate`；结果和来源一起提交，不提交临时锁、凭据或环境私密数据。
5. `npm run prepare:site` 可在工作副本生成。推送 `main` 后 GitHub Actions 同样生成、测试和发布。网页仅发布 `dist/`，完整档案从仓库读取。

## 琵琶识别修订（2026-11-13）

依据实测反馈取消四弦夹角的整体否决、单帧速度门槛和较短的可拨区。逐弦使用独立接近/离开状态；累计小位移支持横向穿弦和连续往返（用户已明确单拨定义；只靠近或未穿过就收回不发声），快速跨帧扫弦保留经过顺序。相邻弦的判定带宽按间距缩小，停留和小抖动不重复。

PipaHandStabilizer 根据手腕连续性保持左右角色，在左掌坐标中稳定五个弦端；右食指靠近时保留被遮挡弦端。界面可固定琴弦，固定后画面位置不再跟随左手，切换乐器/关闭摄像头会解除。它无法恢复模型完全丢失的右手，也不是跨手 3D 碰撞。

音色去除固定 480/980 Hz 杂频与非整数泛音，强化基音、减短高频衰减，并逐半音生成，避免三半音采样移调的听感跳变。《茉莉花》的 MIDI 音高和存档未改写。当前仍是合成音色，音色好听程度与真人识别率不能由自动测试证明。新增各弦短单拨、缓慢穿弦、弦端拨弦、窄夹角、拇指遮挡、左右翻转及固定弦测试。


## 双拨弦点与二次固定（2026-11-13）

- `dist/lib/pipa-layout.js`：一次固定保存四弦；二次固定保存两组拇指—中指/食指连线，弦号依次为中指 1、食指 2、中指 3、食指 4。第二次只补充后两弦，不移动第一组。定位中禁止摄像头触发；双手模式必须固定后演奏，避免左食指一边拨弦一边拖弦。切换乐器、关闭摄像头、手动换手或画面比例改变会清除布局，模式切换保留布局。
- `dist/lib/pipa-input.js`：每个指尖独立检测状态、扫弦编号和排程。单手是右 8/12 点，双手是左 8 与右 8；固定布局使用共同尺度和完全相同的阈值。左手用于定弦的平滑不作用于左手拨弦点，拨弦两手均使用原始点。短连拨不再要求退到原来较宽的离弦半径，仍需观测到真正穿弦，不把停留和抖动变成连发。
- 自由模式同一拨弦点的连续扫弦间隔 28 ms，排程最多领先 84 ms；新一拨立即开始，另一只手不排在前一只手后面。梦想模式每点每拨计一次，两点同帧拨动推进两事件，第二音约延后 22 ms；引导模式保留原谱等待和指定弦判断。暂停、切换和重新定位会取消未播放声音。
- 根据垂直弦方向的掌宽/秒速度计算力度，倍率为 `0.94 + 0.12 * (1 - exp(-speed / 3))`；即 MIDI 力度范围约 ±6%，不改变音高。鼠标划弦同规则，按钮/键盘用中等力度。`pipa-audio.js` 按拨弦点和弦保留独立音频声部，同手同弦重拨才收旧尾音，避免双手同音互相截断。音乐旋律与伴奏使用独立声部键。
- `tests/pipa-duo.test.mjs` 覆盖双点四弦各 40 次 30 ms 连拨、失踪单手不干扰另一手、第一/第三弦独立访问、固定顺序、速度与排程。`npm run test:pipa-duo` 运行完整 Worker 到页面的双手模拟及 OfflineAudioContext 渲染，检查双手同音能量和暂停取消未来声音。与 `npm run test:pipa`、钢琴回归测试一起运行。模拟结果不能代表真人遮挡条件下的识别率。

## 识别资源加载与兼容回退（2026-11-13）

- 已复现原网页的两层超时冲突：外层 180 秒，但模型下载仍在 60 秒被中断；正常持续传输也会失败。线上资源本身可返回 200，当前测试线路仍出现低速和连接重置，不能以延长外层期限解决。
- `dist/lib/hand-assets.js` 并行加载模型、JS 和按 SIMD 能力选择的 WASM。以接收数据更新 30 秒停滞计时器，最多重试两次，取消会中断下载；不依赖 `AbortSignal.timeout`。界面报告解压后的资源加载量，不能当作网络传输字节数。每份资源按固定 SHA-256 校验后独立存入 CacheStorage；缓存不可用时回到网络，损坏条目重新下载。资源更新必须同步该模块的文件大小和哈希。
- `hand-worker.js` 不再负责网络下载。资源通过 Blob URL 和模型字节交给识别引擎，避免初始化内部隐藏下载。`hand-runtime.js` 显式传入画布，避开依赖库按 Safari 标识误用 `document` 的路径；启动前进行一次空白帧推理。Worker 初始化有 20 秒期限，失败后 `hand-client.js` 自动采用主线程兼容路径（45 秒初始化期限）；首帧传输或推理失败也可回退。兼容路径的推理可能占用页面线程，优先保留正常设备的 Worker。
- 模型、置信度、演奏阈值、音色、音乐内容和两种乐器的输入规则未调整。资源仍来自本仓库的 GitHub Pages，不增加外部模型源。缓存可减少后续下载，但不能保证首次访问的网络速度。
- 新增 `test:hand-loading` 与 `test:hand-loading:slow`，覆盖真实初始化和帧推理、Safari/iOS Chrome 标识分支、缺失 Worker 画布/WebGL/ImageBitmap/SIMD、无缓存权限、启动挂起、首帧失败、HTTP 重试、损坏缓存与取消。慢速测试通过本地限速服务器运行真实模型下载，超过旧 60 秒门槛。浏览器标识测试仍在 Chromium 内执行，不代表操作系统真机覆盖。

## PC 识别启动修正（2026-11-14）

识别脚本通过本站静态 URL 执行。模型和 WASM 仍按内容校验并缓存，已验证的 WASM 字节通过随库适配的 wasmBinary 参数交给 Emscripten。prepare:site 从上游原件 vision_bundle.mjs 生成 vision_bundle_bytes.mjs。旧页面仍能按原摘要校验上游原件。下载连接中断时保留已接收的字节，重试请求剩余区间；服务器返回整份文件时重新组装，并校验最终摘要。桌面浏览器回归覆盖仅允许同源脚本的 Worker 和主线程。
